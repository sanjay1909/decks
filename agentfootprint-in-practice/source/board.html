the startThe model is an AI: it reads text and writes text. What it reads before answering is the prompt; longer means slower and costlier. It has never seen your data.
a toolSo the app gives it tools: small programs, each with a name and a description. The model writes the name of the one it wants; the app runs it.
it worksWith two tools it picks the right one. Most demos stop here. The dashed boxes are what the app needed as it grew.
level 1 · the problemThe app grew to 92 tools. The model reads all 92 descriptions every time, and picks the wrong one.
level 1 · the fix: skillsThe tools are grouped into 25 skills. The model picks a skill first, then sees only that skill’s few tools.
level 2 · the problemThe answer needs a link no single tool returns. Nothing tells the model where that fact lives, so it guesses.
level 2 · the fix: the mapA map of what exists, how it connects, and which skill finds each fact. It rides along with every question: about 6.5k tokens (word pieces).
level 3 · the problemSome answers are big tables, and every row goes into the prompt. Adding up thousands of numbers by eye, the model gets it wrong.
level 3 · the fix: codeThe model writes a small program; the app runs it on a copy of the data, with no passwords. Key numbers use 3 checked calculations instead.
level 4 · the problemThe math is right, but all 12,480 rows go to the model again with every follow-up: slower, costlier, and big tables can exceed what it can read.
level 4 · the fix: referencesThe app keeps the table aside. The model gets a short label instead: what it is, its size, its columns; never the rows.
level 5 · the problemEach question starts fresh: the model sees only its prompt. A follow-up about an earlier answer finds the details gone, so it guesses.
level 5 · the fix: the run logEvery run is recorded. The model can look back at what it did before, and answer from that record.
level 6 · the problemOne sentence was checked and one was guessed, and nothing in the answer tells you which.
level 6 · the fix: the ledgerEvery tool call notes why it was made and what it found: fact, open, noise, ruled out. The answer is built from those notes: known, not sure, ask.
the whole appSkills, map, code, references, run log, ledger: six problems, met one at a time. This is how an AI assistant grows.
the boundary · greenGreen is the library, agentfootprint: the machinery behind every fix. None of it knows anything about storage.
the boundary · purplePurple is the app: it fills the library’s frames with its own skills, tools and map, and brings its data, its calculations and its screen.
what the library is forAn AI assistant meets these problems as it grows. agentfootprint solves them once, so an app brings only what it knows.open source, MIT licence · npm install agentfootprint
what it does not claimIt does not make the model right; it shows what was checked, guessed or missing. Measured: the checked calculations passed 29 of 29 wordings; the map’s gain came mostly from one question.
next · first, todayToday a question about an average makes the model write code, run it over the raw samples and check it, all while the user waits.
next · the stats builderThe pipeline already collects every 5 seconds. A stats builder sums the samples as they arrive: one summary every 5 minutes, each with its trail.
